F:\wow-forever (not a git repo) holds gameplay optimization notes for World of Warcraft: Forever (Classic+ release,
launches 2026-11-04). Organized strictly **by class** (9 lowercase class folders), with `_reference/` and
`_templates/` for cross-class material. Talent optimization was built first (2026-09-15) on Classic Era
community builds as the baseline; the scorer (`_reference/data/scorer/`: effects parser + manual effect files per
game, spec models incl. healer/tank, profiles, optimizer, level order, respec.py, compare_effects.py, loop_audit.py +
loops/<class>.json) covers all nine classes and reproduces the Classic community builds.

State as of 2026-09-26: Forever data is the **beta client build 1.60.1.70009** merged from three datamines by
`refresh_forever_talents.py` (raw pulls archived in `_reference/data/raw/`, demo snapshot kept there too); every
class also has `spells/README.md` generated by `build_forever_spells.py` from `_reference/data/forever-spells/`.
Two trees were renamed (Shadow, Elemental), talents cut/renamed (Balance of Nature, Vitality, Improved Holy Strike,
Crusade; Mangle→Primal Bite, Primal Fury→Blood Frenzy, Drain Hope→Wrack, Restless Blades→Flawless Execution).
`_reference/beta-refresh-2026-09-25.md` holds the before/after build table. Since 2026-09-26 the scorer's numbers are
calibrated rather than hand-tuned: leveling values and shares to the fight lab ([[wow-forever-fightlab]]), raid values
and shares to the community simulators ([[wow-forever-raidsim]]: ElliotWood/Forever fork for Forever, upstream
wowsims/classic for the Classic-era check), all driven by `_reference/data/rebuild.py`.

**Layout since 2026-09-27 (user request):** every class folder is split by scenario: `leveling/` (README index, guide.md,
rotation.md, respec-plan.md, builds/, fightlab/, optimizer/), `raid/` (README index, rotation.md, gear.md, consumables.md,
builds/, raidsim/, heallab/, optimizer/) and `pvp/` (README, builds/; no rotation: PvP play depends on the fight), plus
spells/ and talents/ (forever/proposed-builds.json + trees/audit/adaptation notes; classic-baseline/ reference pages).
`_reference/data/paths.py` is the only place that knows the layout; `readme_sections.py` lets each renderer replace its own
`## ` section of a scenario README; the class README keeps its hand-written top and a generated "Where to find things"
section. A build's folder comes from its `content` (leveling/solo -> leveling, raid/dungeon -> raid, pvp -> pvp). Rotations are per build
(`render_rotations.py`: the simulator's APL filtered to the lines each build casts, ours and the simulator's presets; the
fight lab's casts per kill per leveling build); raid README "DPS ranking" + class README "Raid DPS ranking" + a rank table on each
build page compare our builds with the community simulator's own (user request 2026-09-27).

**Why:** The user's premise is that Forever reuses the Classic talent system, so Classic optimal builds are the
starting point; the trees are revamped, so every class has an audit + adapted builds. The user wants everything
stats-based with reasons traceable to sources, buffs/nerfs preserved, healing/tanking modelled, respecs considered,
the folder "extremely organized", periodic full re-pulls of released data to fine-tune the model, and one command
that rebuilds everything. The user is not playing the beta: every number is a simulation of stated assumptions.

**How to apply:** Follow `F:\wow-forever\CLAUDE.md` (JSON is the source of truth; run
`python _reference/data/validate_builds.py && python _reference/data/render_builds.py` after edits; never hand-edit
generated `.md`). Change scorer inputs (`*.manual.json`, `specs/*.json`, `profiles.json`, `loops/*.json`), never
`*.parsed.json`; fitted entries (notes "Fight lab calibration" / "Raid sim calibration") are re-fitted by
`rebuild.py`, not hand-edited. Since 2026-09-27: talent-created abilities are gated sources (`enabled_by`), raid-buff
talents carry measured raid values (`raidsim/buff_value.py`), tanks are calibrated on threat + damage taken, healers on
the healer lab (`_reference/data/heallab/`), every class but the druid has an AoE grinding variant, every loop-audit flag
has a documented reason, and `check_beta_build.py` says whether a newer beta client exists (build 70009 still current on
2026-09-26). Known open items: the Bastion/Focused Rage table-vs-notes discrepancy, a druid AoE variant, healer gear from the
item database, `professions/` not started; PvP has builds and a tuned PvP profile but no simulator. See [[wow-forever-beta]] and [[bash-heredoc-quirks]].
